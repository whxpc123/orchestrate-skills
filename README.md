# Orchestrate Skills

一个面向 Codex 的通用 Skill 编排器：先把复杂目标拆成可验证的步骤，再为每一步选择已安装或可发现的 Skill，向用户展示完整执行计划，并在获得明确确认后自动安装和执行。

它适合这类请求：

- “完成这个项目需要哪些 Skills？”
- “把几个 Skills 串成一条工作流。”
- “先规划，等我确认后再自动执行。”
- “缺少某个 Skill 时帮我搜索，但不要直接安装。”

## 核心能力

- 先规划、后执行，严格保留用户确认边界
- 将目标拆成有输入、输出、依赖和验收条件的步骤
- 优先复用本地已安装 Skills
- 通过 `find-skills` 或内嵌发现流程搜索缺失 Skills
- 核验候选 Skill 的安装量、来源、GitHub stars 和安全信号
- 输出精确的 `install_manifest`，确认前不安装
- 支持依赖排序、安全并行、失败重试和批准后的回退方案
- 登录、密钥、公开发布、生产修改和删除等高影响动作必须单独确认
- 使用执行台账记录每一步的状态、产物和验证结果

## 工作方式

1. 明确目标、交付物、限制和完成标准。
2. 将工作拆成可独立验证的步骤。
3. 为每一步匹配本地 Skill、外部候选或内置通用能力。
4. 输出冻结的工作流版本和安装清单。
5. 等待用户明确批准对应的 `workflow_id` 与 `revision`。
6. 仅安装批准清单中的 Skills，并按依赖顺序执行。
7. 验证所有交付物，通过后才宣告完成。

## 安装

```bash
npx skills add whxpc123/orchestrate-skills@orchestrate-skills -g -y
```

`-g` 会把 Skill 安装到用户级 Skill 目录，供 Codex 在不同项目中复用。

## 使用示例

```text
使用 $orchestrate-skills 规划完成一个微信小程序需要哪些 Skills，
先给我完整流程和安装清单，等我确认后再自动执行。
```

也可以用于内容生产、产品开发、数据分析、研究、设计和发布等多阶段任务。

## 计划输出

每份计划都会包含：

- 稳定的 `workflow_id`、版本号和审批状态
- 目标、交付物、完成标准与假设
- 有序步骤、依赖、Skill 来源和选型理由
- 每一步的输入、输出、验证、执行方式和副作用
- 待安装 Skill 的准确命令与候选证据
- 未解决项、批准回退和替代方案
- 本次确认允许和明确排除的操作
- 可直接回复的精确确认语句

## 安全边界

一般的“可以”“看起来不错”或设计讨论不会触发执行。只有用户明确确认当前工作流 ID 和版本后，Skill 才能开始安装和执行。

以下操作即使出现在计划中，也必须在执行到对应步骤时再次确认：

- 登录或输入密钥
- 支付或购买
- 发送消息
- 公开发布
- 修改生产环境
- 删除数据或不可逆覆盖

```text
orchestrate-skills/
├── SKILL.md

├── agents/

└── references/
```

其中 `SKILL.md` 定义编排流程，`workflow-contract.md` 定义计划格式、审批规则、执行台账和恢复策略。
